# 质量检查与迭代

### M. 迭代与自检

每次修改先说明本次改变什么，再把用户的反馈转换为可见操作。保持已确认内容稳定，避免从零重抽导致身份漂移。

| 反馈 | 先处理的对象 |
| --- | --- |
| “太脏” | 噪点、无差别划痕、随机碎饰、暗部细节堆积 |
| “太像其他角色” | 剪影、身体比例、脸部结构、重复腰带与动作 |
| “不像这个角色” | 最关键的原型锚点、物种结构、标志性道具 |
| “太西方化” | 当前角色的面部骨相、服装结构与文化语汇 |
| “太华丽” | 大面积雕花、金边、重复首饰与无功能装甲 |
| “不够高级” | 比例、材质对比、光线、视觉中心，避免只加装饰 |
| “角色不一致” | 对照基准逐项找出发生变化的字段 |
| “武器不对” | 武器类型、长度、连接、握持与数量关系 |

输出前检查：用户硬约束是否满足；身份锚点是否可见；图文是否一致；身体与道具是否可信；参考图是否串用；材质和细节是否有主次；有没有新增无关信息。

若实际生成图片，依据图片检查，而不是依据提示词宣布成功。把未通过的具体部位写清，优先局部修正。没有生成图片的文字任务，只能说明完成了规则或提示词检查，不能声称画面验证通过。

## 检查结果怎么说

- 只写了提示词：说明完成了文字组织与约束检查，不说“图片完全一致”。
- 图片有明确错误：指出可见错误、涉及的硬约束和下一次要修正的区域。
- 被裁切或遮挡：把无法检查的项目标为未验证，不补写成功结论。
- 任务已满足：直接交付，不自动发起额外变体或重复测试。
